git-purge-branches(1) Manual Page

Name

git-purge-branches - delete local branches merged into a commit

Synopsis

git purge-branches [-n | --dry-run] [-e | --equivalent] [-i | --interactive] [--include=<pattern>]…​ [--exclude=<pattern>]…​ [--older-than=<days>] [<commit>]
git purge-branches -h | --help | -v | --version

Description

Deletes the local branches merged into <commit>, by default the default branch of origin, origin/HEAD, or HEAD in a repository without it. A branch is merged if its tip is reachable from <commit>.

Five kinds of branches are always kept. Branches checked out in any worktree are kept, which includes the current branch. Every branch is merged into itself, so a branch given as <commit> is kept as well. The default branch of each remote, such as main for origin/HEAD, is kept, since a topic branch contains the branch it started from. Branches that match a pattern of purge-branches.keep or are exempt by branch.<name>.deleteMerged are kept, as described under CONFIGURATION.

Merged branches are deleted with git branch -d, which refuses a branch that is not merged into its upstream or, without an upstream, into HEAD. A branch merged into <commit> can therefore remain if <commit> is not HEAD, or if its upstream lacks commits of the branch.

After deleting, the command prints a git branch command per deleted branch that restores the branch at its commit.

A remote that rebases a branch before merging it, as GitLab and GitHub offer, merges copies of its commits with other hashes. The local branch then keeps the original commits and is not merged. --equivalent also deletes such branches.

Options

Short options may be combined, such as -en for -e -n.

-n, --dry-run

List the branches that would be deleted and delete nothing. Each line holds the name of a branch and, after a tab, the reason: merged, or equivalent for a branch that --equivalent selects. A merged branch that git branch -d would refuse is listed as well.

-e, --equivalent

Also delete branches whose commits all have an equivalent in <commit>, as git cherry determines by comparing the changes of commits. A branch that contains an empty commit or a merge commit is kept, since git cherry matches an empty commit with any other and omits merge commits, whose own changes it cannot compare. These branches are deleted with git branch -D, which discards the original commits.

-i, --interactive

List the branches to delete as --dry-run does and ask once before deleting them. Only the answer y or yes, in any case, deletes them, while any other answer or none keeps every branch. With --dry-run, nothing is asked or deleted.

--include=<pattern>

Delete only the branches that match the glob pattern, which matches the whole name of a branch, as for purge-branches.keep. The option may be given several times, and a branch then needs to match one of the patterns.

--exclude=<pattern>

Keep the branches that match the glob pattern, even if they match --include. The option may be given several times.

--older-than=<days>

Delete only the branches whose last commit is older than the given whole number of days, such as 30.

The value of these options may also follow as the next argument, such as --include 'feature/*'.

-h, --help

Print a usage summary and exit.

-v, --version

Print the version and exit.

<commit>

The commit the branches are merged into, by default origin/HEAD, or HEAD without it. Options may precede or follow it.

Exit status

0

All selected branches were deleted or, with --dry-run, listed.

1

git branch failed to delete a branch. The remaining branches are still deleted.

2

An unknown option or more than one <commit> was given.

Any other status is that of git when listing the branches or reading their configuration fails, such as 128 outside a repository, for an invalid <commit> or for a branch.<name>.deleteMerged that is not a boolean. No branch is deleted in that case.

Configuration

purge-branches.keep

A glob pattern, such as develop or release/*, whose matching branches are never deleted, not even with --equivalent. The pattern matches the whole name of a branch, and * matches slashes as well. The setting may be given several times, such as with git config --add.

branch.<name>.deleteMerged

If false, branch <name> is never deleted, not even with --equivalent. Defaults to true. git branch --delete-merged honors the same setting.

Examples

Delete the branches merged into the default branch of origin:

$ git purge-branches

After fetching, list the branches merged into the default branch of origin, including those that the remote rebased before merging, then delete them:

$ git fetch --prune
$ git purge-branches --dry-run --equivalent
$ git purge-branches --equivalent

Comparison with git branch --delete-merged

git branch --delete-merged <pattern> also deletes merged branches, but selects them by their upstream instead of by a commit. It deletes a branch only if the configured upstream of the branch matches <pattern> and contains its tip. It keeps a branch without an upstream and a branch whose upstream no longer exists, such as a topic branch whose remote branch was deleted after the merge. It also keeps a branch whose push would update its upstream, such as a topic branch pushed to a remote branch of the same name. Commits that a remote rebased before merging count as unmerged.

git purge-branches instead deletes the branches merged into <commit> whether they have an upstream or not, within the checks of git branch -d described above, and with --equivalent also those that a remote rebased before merging. It cleans up topic branches whose remote branches were merged and deleted. git branch --delete-merged cleans up local branches that track a branch of a remote, such as its main branch, once their work has landed there.
